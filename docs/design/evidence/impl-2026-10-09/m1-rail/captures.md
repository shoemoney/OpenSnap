## How this set was made

- `sh tools/eye-dump-audit.sh --groups pairs,sizes,fullscreen,states --appearances light,dark --icons both` at source `616c9b0` (clean tree). The harness is the only capture path: throwaway bundle id, sandbox, real-store guard (stores unchanged, see `safety.txt`), cleanup before the final compare. No `original/` fixtures; every shot is the synthetic gradient-and-fake-windows fixture.
- **FA unavailable:** no FontAwesome subset fonts are bundled in this build, so `--icons both` ran `sf` only and recorded `fa` as unavailable (`manifest.json` → `unavailable`, `faMode`). Nothing is faked.
- Each PNG is the one stored copy, scaled to at most 1200 px wide (so 980 pt windows are shown at about 0.61 of their native 2x pixels). Native pixel size is in `manifest.json` (`pixelSize` vs `storedPixelSize`).
- `layout/<stem>@616c9b0.json` beside each editor capture is the per-capture metrics file: per-group frames of both bars, gaps, free width, status width with and without the Original-size checkbox, viewport rect and trailing margin, canvas centring, Frame hole vs capture rect, and `"rail": "absent"` (neither retired group id exists, trailing margin is 12 pt, no narrow view parked on the trailing edge). **All 80 layout files say `rail: absent` with a 12 pt trailing margin and no overlapping groups.**

## Findings (reported, product code not changed)

1. **Size popover overhangs the window by about 83 pt at every width** (`insideWindowHorizontally` false in `S30` meta); the pill is the rightmost control so a 346 pt-wide popover centred on it hangs past the edge. It stays on screen.
2. **At 980 with the Original-size checkbox shown, the status label is 175 pt**, so nearly every status truncates ("Arrow · Unsaved ch…") and the Frame hint ("Frame: position, then Snap", needs 219) still truncates in Frame mode on a large shot. The hint shortening only fits when the checkbox is hidden.
3. **A small canvas lands top-left, not centred, when the window is already at its minimum width** (`S34-small-canvas-w980`, gaps 0 / 656). Resizing the window by 2 pt re-centres it (`S34-small-canvas-w980-after-resize`). The same state is visible in `S12-frame-mode`, where the window is sized to canvas + 20 and the canvas has gap 0 left / 20.7 right and 0 top / 20 bottom instead of 10 / 10. The CenteringClipView re-centres on viewport resize but not when only the document changes.
4. **`frameViewportScreenRect` uses `canvas.visibleRect`, which for a canvas smaller than the viewport returns the whole viewport** (raw visibleRect `[-478,-236,1256,652]` for a 300×180 canvas at 1280). In `S12-frame-mode` the capture rect equals the hole, not the canvas clipped to the hole (`captureEqualsCanvasClippedToHole` false). This contradicts the doc comment on the property ("the centred canvas for a smaller one"). Needs a product check before anyone relies on it.
5. Legacy scrollers are in use (the capture host has a mouse): they take a 17 pt gutter from the viewport and show a white corner box; overlay scrollers would not.
6. Full screen: accent fills on Snap and the selected tool disappear in the capture, and the populated window tints salmon from the bleed layer.

## Known gaps

- **Live screen capture:** nothing here captures the screen; Frame mode is imaged through the window server's own window only (transparent hole), not an actual capture of the desktop behind it.
- **Real (non-offscreen) popover translucency:** a popover captured on its own bakes its material against nothing (grey); here each popover is stacked above its window image, so the frame colour is not what a user sees over live content. `popoverIsOpaque` is false for all of them.
- **VoiceOver speech:** AX trees were written to the raw run but not packed or listened to; no speech was verified.
- **Reduce Transparency / Increase Contrast:** not captured; injected DisplayOptions arrive with OSN-061.
- **FA mode:** unavailable, no Font Awesome fonts bundled; SF Symbols only.
- Size drag, preset click, Escape, reopen persistence, and Color/Size/Font acting on a selected element with one ⌘Z revert are behaviour, not appearance: they are not exercised by the harness and rely on the unit suite.
- The BEFORE twins are default-height windows and a different synthetic size for some surfaces, so before/after pairs are comparable in layout, not pixel-aligned.
